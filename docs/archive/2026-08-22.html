SWE-bench Science: Can Coding Agents Resolve Engineering Tasks in Science? SWE-bench Science：编程智能体能解决科学工程任务吗？

🧑‍🔬 Zhipeng Xu, Jiahao Lu, Yining Zheng, Yuxin Wang et al.

🎯 新基准揭示：最强AI编程智能体修科学代码错误仍超半数失败
A new benchmark reveals that even the best AI coding agents fail more than half the time on real scientific software bugs.
🗣️ 一句话比喻 · Plain-English Analogy就像请一个很厉害的全能修理工来修一台精密科学仪器——他工具用得很溜，但如果不懂仪器背后的科学原理，只是把表面的零件换了，实验还是会出错，结果一塌糊涂。Think of it like hiring a brilliant all-around handyman to fix a specialized piece of lab equipment — they might know tools really well, but if they don't understand the science behind the machine, they'll patch the wrong part and the experiment will still give you garbage results.
维度 中文 English
❓ 待解决
的问题		 AI编程智能体越来越擅长修复普通软件的漏洞，但科学研究也依赖大量专业代码——比如气候模型、基因组分析或物理仿真程序。这些代码出错，科学结论就可能跟着出错。现有的AI编程测试不考察科学软件，所以我们根本不知道这些智能体在真正的科研场景下到底可不可靠。 AI coding agents are getting good at fixing everyday software bugs, but science runs on specialized code too — think climate models, genomics pipelines, or physics simulations. When that code breaks, wrong science can follow. Existing tests for AI coders don't measure how well they handle scientific software, so we have no idea how reliable these agents really are when the stakes involve real research conclusions.
💡 解决
的亮点		 • 首个专门针对科学软件工程的基准测试，覆盖20个科学领域、98个GitHub仓库、119个真实修复任务。• 设计三种任务范式：用户反馈的Issue、专家探索性任务、跨系统工程集成，模拟真实科研场景。• 发现"科学知识"是把双刃剑：准确的知识能提升修复效果和效率，但错误对齐的知识会让智能体陷入"锚定效应"，反而变得更差。 • First benchmark specifically targeting scientific software engineering, spanning 119 real bug-fix tasks from 98 GitHub repos across 20 scientific domains. • Three task types capture different real-world scenarios: user-reported issues, expert-crafted explorations, and cross-system integration challenges. • Reveals that scientific knowledge can be a double-edged sword: good guidance helps agents fix bugs faster and cheaper, but bad guidance actually makes agents worse by anchoring them to wrong assumptions.
🧪 实验
内容		 研究团队在119个任务的SWE-bench Science基准上评测了多个顶尖AI编程智能体，包括Claude Code（Opus-4/5）等主流模型。任务来自98个GitHub仓库、横跨20个科学领域，分为三种范式。评测指标为pass@1（首次尝试修复成功率）。他们还进行了配对消融实验，去掉科学知识引导、仅保留代码工程上下文，以隔离领域知识的实际影响。 The team evaluated several state-of-the-art AI coding agents — including Claude Code with Opus-4/5 and other leading models — on the 119-task SWE-bench Science benchmark. Tasks were drawn from 98 GitHub repositories spanning 20 scientific domains and organized into three paradigms (Issue-driven, Expert-exploratory, Engineering-integration). They measured pass@1 (whether the agent fixes the bug correctly on the first try). They also ran a paired ablation study removing explicit scientific guidance while keeping the code and engineering context intact, to isolate the effect of domain knowledge.
📊 实验
结果		 最强智能体Claude Code（Opus-5 max）的pass@1低于50%，即超过一半的科学代码漏洞它无法正确修复。研究归纳出四类反复出现的失败模式：缺乏领域知识、探索浅显或走错方向、修复不完整、无法举一反三。消融实验显示：对齐良好的科学知识能提升平均修复表现并节省token消耗，而对齐差的知识则会造成"锚定效应"，不能改善精确修复成功率。 The best-performing agent, Claude Code with Opus-5 (max), achieved a pass@1 below 50% — meaning it fails to correctly fix scientific bugs more than half the time. Four recurring failure patterns were identified: lack of scientific domain knowledge, shallow/misguided code exploration, incomplete fixes that miss edge cases, and inability to generalize scientific reasoning to new situations. The ablation study showed that well-aligned scientific guidance improved average performance and reduced token usage, while poorly-aligned guidance caused anchoring effects and did not improve exact repair success rates.
🏁 结论 SWE-bench Science证明：当前最强的AI编程智能体在科学软件上还远不够可靠，即使是最顶尖的模型也有超过半数的任务失败；同时，领域知识的质量至关重要，用得好能提升表现，用得不好反而帮倒忙。这个基准为研究界提供了一个严格的测试平台，推动AI智能体在高风险科研计算中的进步。 SWE-bench Science proves that today's best AI coding agents are not yet reliable enough for scientific software — even the top model fails over half the time — and that domain knowledge is a double-edged sword that can help or hurt depending on its quality. The benchmark offers the research community a rigorous testbed to study and improve AI agents for high-stakes scientific computing.

⚙️ Method · 方法详解

研究团队从真实科学GitHub仓库中精心筛选了119个修复任务，涵盖生物、天文、化学、物理等领域。每个任务都有问题描述、出错代码和验证修复是否成功的测试用例。他们让多个主流AI编程智能体来完成这些任务，记录成功率。此外，他们还做了一个"对照实验"：把同样的任务中的科学说明去掉，只保留代码和工程上下文，以此单独测量"科学知识"到底帮了多少忙，或者添了多少乱。 The researchers built SWE-bench Science by carefully curating 119 bug-fix tasks from real scientific GitHub repositories — covering fields like biology, astronomy, chemistry, and physics. Each task comes with a clear problem description, the broken code, and a test to check if the fix works. They then ran multiple leading AI coding agents on these tasks and measured how often they succeeded. They also ran a clever "ablation" experiment: they gave agents the same tasks but stripped out the scientific explanations, keeping only the raw code and engineering context. This let them isolate exactly how much the scientific knowledge actually helped (or hurt).

🌟 Why It Matters · 为什么重要

现代科学越来越依赖软件——从新药研发到气候预测——代码出错可能让多年研究付诸东流。这个基准敲响了警钟：AI编程工具在科研场景中还不够可信，同时也为未来的改进指明了方向。 Science increasingly depends on software — from drug discovery to climate modeling — and bugs in that software can invalidate years of research. This benchmark is a wake-up call showing that AI coding tools aren't yet trustworthy for scientific work, and it provides a clear roadmap for what needs to improve.

AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement AI4AI-Bench：用于递归自我改进的算法设计中的大语言模型智能体基准测试

🧑‍🔬 Yizhe Chi, Wenyi Li, Deyao Hong, Xiaoqiu Wang et al.

图 Figure · Page 2 of paper

🎯 首个测试AI能否自主改进训练算法的专业基准
The first benchmark measuring whether AI agents can genuinely redesign the algorithms that train AI systems.
🗣️ 一句话比喻 · Plain-English Analogy就像问一个厨师能不能改良培养下一代厨师的教学课程——不是换食材、不是调火候，而是重新设计整套教学方法。AI4AI-Bench就是给这件事打分的考官，结果发现大多数"厨师"连改课程的勇气都没有，敢改的人也只把课程质量提升了不到两成。Imagine asking a chef to redesign the cooking school curriculum that trains future chefs — not just swap ingredients or adjust oven temperature, but rewrite the entire teaching method. AI4AI-Bench is the judge scoring that effort, and it turns out most AI "chefs" don't even dare touch the curriculum, and the brave ones only improve it by less than 20%.
维度 中文 English
❓ 待解决
的问题		 我们一直想知道：AI能不能自己改进"制造AI的方法"？这就像问一个工厂的机器人能不能改造自己的生产流水线，让下一批机器人更厉害。现有的测试根本无法回答这个问题，因为它们只测试"收集更多数据"或"调调参数"，而不是真正改变AI的学习方式。 Can an AI improve the very process used to build AI? Imagine asking a robot to redesign its own factory assembly line so every future robot comes out smarter. Existing AI benchmarks don't test this — they reward tweaking small settings or collecting more data, not actually rewriting how a model learns from scratch.
💡 解决
的亮点		 • 首创"冻结代码库"测试形式：AI必须真正重写训练算法，而不是调参或换数据，测试更纯粹、更严格 • 统一评分尺度设计巧妙：0分=随机乱猜，0.1分=原始算法，1.0分=理论最优，让10个完全不同的任务能公平比较 • 揭示关键鸿沟：大多数AI根本不敢"真正改变学习方式"，只有少数会这样做，但一旦做了，得分明显更高 • 开源全部数据：任务、评估器和每份提交记录全部公开，方便随时重测 • Novel "frozen repo" format: agents must actually rewrite the training algorithm, not just tweak hyperparameters — a much purer test of AI-driven innovation • Clever universal scoring scale: 0 = random noise, 0.1 = the original algorithm, 1.0 = theoretical best — making 10 wildly different tasks fairly comparable • Reveals a key gap: most AI agents never dare change how learning actually works; the few that do score significantly higher • Fully open-sourced: tasks, evaluators, and every scored submission released for reproducibility
🧪 实验
内容		 研究在10个涵盖不同训练算法家族的冻结代码库上，测试了6个不同AI系统的29种配置（包括不同推理强度的设置）。基线是每个代码库自带的原始算法（得分0.1），比较对象是各任务的理论最优解（得分1.0）。评估指标为统一归一化得分，且评分器对被测智能体完全隐藏，防止作弊。 The study tested 29 configurations of 6 different AI systems across all 10 benchmark tasks. The baseline for each task was the original algorithm shipped with the repository (scored at 0.1), compared against the theoretical task optimum (scored at 1.0). A hidden evaluator scored each submission, and results were analyzed by whether the agent actually changed the learning mechanism vs. just surface-level code edits.
📊 实验
结果		 • 29种配置平均得分仅0.166，最强系统也只达到0.250——连"原始算法"到"理论最优"这段距离的五分之一都没走完 • 真正改变了学习方式的提交平均得0.226，而没有改变的只有0.126，差距显著 • 更强的推理能力主要带来"敢于改变"的意愿：愿意改变学习算法的提交比例从8%跃升至64%，平均分从0.094升至0.196 • Average score across 29 configurations was just 0.166; even the best system only reached 0.250 — less than one-fifth of the way from the original algorithm to the theoretical optimum • Submissions that actually changed how the model learns averaged 0.226, vs. only 0.126 for those that didn't — a big meaningful gap • More reasoning effort mainly bought "willingness to try": the share of submissions that changed the learning algorithm jumped from 8% to 64%, and mean score rose from 0.094 to 0.196
🏁 结论 本文证明，当前最强的AI智能体在"设计更好的AI训练算法"这一核心能力上仍然极为有限——即使是最好的系统，也只走完了从"现有算法"到"理论最优"不到五分之一的路程。AI4AI-Bench为未来研究递归自我改进能力提供了清晰、可重复的测量工具。 This paper proves that today's most powerful AI agents are still far from being able to meaningfully redesign the algorithms that train AI — even the best systems barely scratch the surface of what's possible. AI4AI-Bench gives the research community a rigorous, reproducible yardstick to track progress on this crucial frontier.

⚙️ Method · 方法详解

研究者搭建了10个"冻结"的真实AI研究代码库，涵盖10种不同的训练算法类别。被测试的AI智能体有4小时时间在一台高性能GPU上重写训练算法，然后系统从零开始重新运行最多12小时，由一个智能体看不到的独立评分器打分。为了公平比较不同任务，所有得分被映射到同一把"尺子"上：0.1代表原始算法的表现，1.0代表该任务的理论最优解。这样，无论任务多不同，都能直接比较AI的改进能力。 The researchers built 10 "frozen" real-world AI research codebases covering 10 different training algorithm families. Each AI agent gets 4 hours on a powerful GPU to rewrite the training algorithm. The rewritten code is then run from scratch for up to 12 hours, and scored by a hidden evaluator the agent can't peek at. To make all 10 very different tasks comparable, scores are mapped onto one universal ruler: 0.1 means the original algorithm, and 1.0 means the theoretical best possible result for that task.

📐 Key Formulas · 关键公式

\[s \in [0, 1], \quad s=0.1 \Leftrightarrow \text{original algorithm}, \quad s=1.0 \Leftrightarrow \text{task optimum}\]
💡 统一评分尺度：每个任务的得分被归一化到[0,1]区间，0.1代表原始代码库自带算法的表现，1.0代表该任务的理论最优解，0代表无信息基线（随机猜测）。 The universal scoring scale: every task's score is normalized to [0,1], where 0.1 = the original shipped algorithm, 1.0 = the theoretical best possible result, and 0 = a completely uninformative (random) model.

🌟 Why It Matters · 为什么重要

递归自我改进是AI安全和AI能力研究中最核心的问题之一——如果AI能自己改进训练方法，智能提升可能会加速失控。这个基准第一次让我们能科学地、可重复地测量现有AI离这个能力还有多远，为安全研究和能力评估提供了重要工具。 Recursive self-improvement is one of the most critical questions in AI safety — if AI can redesign its own training process, capability growth could accelerate in unpredictable ways. This benchmark gives scientists the first rigorous tool to measure exactly how close (or far) today's AI is from that threshold, which matters enormously for safety planning and policy.

EnvHarness: Awakening Static Worlds for Agent Learning EnvHarness：唤醒静态世界以服务智能体学习

🧑‍🔬 Chengsong Huang, Zifeng Wang, Rujun Han, Jun Yan et al.

图 Figure · Page 4 of paper

🎯 自动改造静态训练环境，精准针对AI智能体弱点的插件系统
A plug-in system that automatically reshapes static AI training environments to target each agent's specific weaknesses.
🗣️ 一句话比喻 · Plain-English Analogy就像一款游戏能观察你玩耍，发现你总是在同一个关卡的Boss前死掉，然后自动帮你生成专门练习那个Boss打法的小关卡——而游戏开发者完全不用重新设计游戏。Think of it like a video game that watches you play, notices you always die at the same boss, and automatically generates new practice levels targeting exactly that boss's moves — without the game developers having to redesign anything from scratch.
维度 中文 English
❓ 待解决
的问题		 AI智能体通过在训练环境中反复练习来学习，就像学生做习题一样。但现有的训练环境是人工搭建的"死题库"：不会随着AI能力的提升而变难，也无法针对AI的具体弱点出题。每换一个领域就要从头搭建新环境，费时费力，还需要专业工程师。 AI agents learn by practicing in training environments — like a student doing practice problems. But today's environments are hand-built and fixed: they don't adapt when the agent improves, and they can't target the agent's specific weak spots. Building new environments from scratch for every domain is expensive, slow, and often requires specialized engineers.
💡 解决
的亮点		 • EnvHarness像一件"智能外衣"，套在已有的静态环境外面，无需改写底层逻辑，跨领域通用，且保留原有的验证机制。• EnvRigger充当自动教练：它观察AI在哪些地方出错，诊断具体弱点，然后自动生成有针对性的练习题来弥补不足。• 整套系统支持"持续共同进化"——AI越来越强，环境也随之动态变难，始终保持挑战性和训练价值。 • EnvHarness wraps existing static environments with a programmable "plug-in layer" — no need to rebuild from scratch, works across different domains without changing the original verification logic. • EnvRigger acts as an automatic coach: it watches the agent fail, diagnoses the exact weaknesses, and generates new challenge scenarios to fix them. • The whole system enables continuous co-evolution — as the agent gets better, the environment keeps adapting to stay challenging and useful.
🧪 实验
内容		 研究团队在四个不同领域的五个基准测试上对EnvHarness进行了测试（涵盖编程、数学、工具使用等任务）。对比对象包括原始静态环境，以及为每个任务专门定制的领域专用环境生成流水线。评估指标包括：AI在未见过的测试实例上的表现质量，以及训练过程中的执行步骤效率。他们还评估了EnvHarness作为强化学习优化信号的效果，观察用它训练的AI是否能持续更好地提升。 The researchers tested EnvHarness across five benchmarks spanning four different domains (including coding, math, and tool-use tasks). They compared it against the original static environments and against domain-specific environment generation pipelines built specifically for each task. They measured both the quality of agent performance on held-out (unseen) test instances and the efficiency of training in terms of execution steps. They also evaluated EnvHarness as an optimization signal for reinforcement learning, tracking whether agents trained with it improved more over time.
📊 实验
结果		 在未见过的测试实例上，EnvHarness相比原始静态环境最高提升了9.0个百分点，同时训练所需的执行步骤减少了9.8%。在四个领域的五个基准测试上，EnvHarness全面超越了原始静态环境和领域专用的环境生成流水线。作为强化学习的优化信号使用时，它能实现持续、精准的策略提升，优于基础强化学习训练方案。 EnvHarness achieved up to a 9.0-point improvement on held-out test instances compared to original environments, while also requiring 9.8% fewer execution steps during training. It outperformed both static environments and domain-specific generation pipelines across all five benchmarks in four domains. When used as an optimization signal for reinforcement learning, it enabled continuous and targeted policy improvement, outperforming baseline RL training setups.
🏁 结论 EnvHarness证明了：无需从零搭建新训练环境，只需一个能观察AI失败、自适应改造已有环境的智能插件层，就能在多种AI任务上大幅提升学习效率和最终性能。 EnvHarness proves that you don't need to build new training environments from scratch — a smart plug-in layer that watches an agent's failures and adapts existing environments is enough to dramatically improve both learning efficiency and final performance across diverse AI tasks.

⚙️ Method · 方法详解

想象EnvHarness是一件套在现有健身器械上的"智能辅助装置"。不需要买新器械，只需加上可调节的附件，根据运动员的弱肌肉群自动调整阻力和角度。EnvRigger则是那位私人教练：它悄悄观察AI智能体做任务，找出它反复失败的地方，然后给"装置"编程，专门生成针对这些失败点的练习场景。整个系统通过标准接口工作，可以无缝接入任何已有环境而无需修改原始代码。生成的新场景还会经过新一轮测试，确保它们有效且真正具有挑战性，才会正式用于训练。 Think of EnvHarness like a smart training harness strapped onto an existing gym machine. Instead of buying a whole new machine, you add adjustable attachments that change resistance and angle based on the athlete's weak muscles. EnvRigger plays the role of the personal trainer: it silently watches the agent (the AI) attempt tasks, identifies where it consistently fails, and then programs the harness to generate more practice scenarios targeting exactly those failure points. The whole system works through standard interfaces, so it plugs into any environment without touching the original code. Once new scenarios are generated, they're tested via fresh practice runs to make sure they're valid and genuinely challenging before being used for training.

🌟 Why It Matters · 为什么重要

为AI搭建训练环境是当前AI开发中最费时费力的瓶颈之一，这篇论文提供了一条无需专业工程定制、跨领域通用的捷径。随着AI智能体越来越多地被用于编程助手、研究工具、决策系统等现实任务，更好、更自适应的训练环境将直接转化为更聪明、更可靠的AI产品。 Building training environments for AI is currently one of the most expensive and time-consuming bottlenecks in AI development — this paper offers a general-purpose shortcut that works across domains without specialized engineering. As AI agents are increasingly deployed in real-world tasks like coding assistants, research tools, and decision-making systems, better and more adaptive training environments directly translate to smarter, more reliable AI products.

The paper designs a strict rulebook for these moves (called "permissible blowups") and, crucially, keeps a running history log of every move made. A key invention called the "global replacement certificate" acts like a referee: it tracks all changes across the entire shape and mathematically guarantees the game will end in a finite number of moves. To handle the unique wild behavior of positive characteristic fields (caused by the Frobenius map), the paper introduces new tools — Frobenius-Hasse towers, filtered coefficient cubes, and a six-row defect calculus — to classify and tame every type of local problem systematically.
